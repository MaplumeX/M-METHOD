# §8 · Finishing Touches

12 rules (§8.1–§8.6). The seventh and last lens: **structure is fine but it still is not
attractive** — take actions from here rather than redesigning.

## §8.1 Supercharge the defaults

Add nothing new; make what is already there perform better.

- Bulleted lists → replace bullets with icons. Checks and arrows are generic; a padlock
  beside security features is more apt.
- Testimonials → promote the quotation marks into a visual element: enlarge, recolor.
- Links → change color and weight; or add a thick custom underline in color that overlaps
  the text slightly.
- Form controls → custom checkboxes and radios, with the selected state in the brand color.
  The cheapest way to add color.

## §8.2 Add color with accent borders

Add a colored accent edge to plain areas: the top of a card, the current nav item, the side
of an alert, a short underline beneath a headline, even the top edge of the whole layout.

**A colored rectangle requires no graphic-design talent and makes things look markedly
more designed.**

## §8.3 Decorate your backgrounds

When hierarchy, spacing and type are all right and the design still feels flat, add
something to a few backgrounds — without redesigning.

**§8.3.1 Change the background color.** Emphasize a panel, or separate page regions. For
energy, use a gradient with **two hues no more than about 30° apart**.

**§8.3.2 Use a repeating pattern.** A subtle, repeatable pattern (Hero Patterns, for
example). It need not cover the whole background — repeating along a single edge works
well. **Keep pattern/background contrast low** so text stays readable.

**§8.3.3 Add a simple shape or illustration.** Simple geometry, a slice of a pattern, a
simplified world map. Same low contrast; don't let it compete with content.

## §8.4 Don't overlook empty states

**Symptom**: the page looks beautiful in mockups full of invented data; after launch a user
navigates in and finds nothing.

**Mechanism**: the empty state is the user's **first** interaction with the feature, not an
afterthought.

**Practice**:

- Add an image or illustration to draw attention.
- Make the call to action more prominent, to encourage the next step.
- **Hide the supporting UI that does nothing until content exists** — tabs, filters,
  search.

Use it to show something interesting. Don't settle for "No data yet".

## §8.5 Use fewer borders

Before adding a border to separate two elements, look for an alternative. Borders work, but
stacked up they make the design busy and cluttered.

**§8.5.1 Use a box shadow.** It outlines the element like a border but is lighter. Works best
when the element's color differs from the background.

**§8.5.2 Use two background colors.** Slightly different backgrounds usually separate
neighbouring elements well enough. **If you already have a color difference and a border,
drop the border.**

**§8.5.3 Add extra spacing.** Pulling elements apart separates groups without introducing any
new UI at all.

## §8.6 Think outside the box

**Mechanism**: preconceptions about how a component looks are not technical constraints. That
we believe a component has one design does not make it true.

- **Dropdowns** are just a box floating on the screen. Split into sections, use multiple
  columns, add supporting text, add colorful icons.
- **Tables** need not be one field per column: merge related columns to build hierarchy; cell
  content need not be plain text — images and color can go in.
- **Radio buttons** as a row of circles is the dullest form available; where the choice
  matters, make them selectable cards.

Constraints are powerful, but sometimes what a screen needs is exactly that bit of freedom.
